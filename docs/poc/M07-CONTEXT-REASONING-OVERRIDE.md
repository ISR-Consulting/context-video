# M07 — Multimodal Context Reasoning

## 0. Purpose

M07 introduces multimodal context reasoning over the immutable perception evidence produced by M05 and M06.

M07 MUST NOT reinterpret AudioObservation or VisualObservation as final context.

The architectural distinction is:

```text
Observation = perception evidence

ContextEvent = derived semantic conclusion
```

The multimodal pipeline therefore becomes:

```text
AudioObservation ────────┐
                         │
VisualObservation ───────┤
                         ▼
                Observation Collection
                         │
                         ▼
                Temporal Correlation
                         │
                         ▼
                 Context Candidate
                         │
                         ▼
                 Semantic Reasoning
                         │
                         ▼
                  ContextEvent v1
```

These are logical stages inside the POC.

They MUST NOT be implemented as separate distributed services.

The M07 implementation remains an in-process Go pipeline.

---

# 1. Architectural decisions

## D1 — Observations are immutable evidence

AudioObservation and VisualObservation are evidence generated by perception adapters.

M07:

- MUST consume them without modifying them;
- MUST NOT clean or rewrite transcripts;
- MUST NOT normalize visual detections by modifying their original values;
- MUST NOT replace provider confidence values;
- MUST preserve observation identity;
- MUST reference the observations used to derive a ContextEvent.

Any semantic normalization required for reasoning MUST happen in internal M07 structures, never by mutating observations.

---

## D2 — ContextEvent is a derived conclusion

A ContextEvent represents what the Context Intelligence pipeline concluded from one or more observations.

The relationship is:

```text
Observation(s)
      │
      ▼
reasoning
      │
      ▼
ContextEvent
```

ContextEvent MUST NOT be treated as another perception observation.

---

## D3 — Temporal correlation happens before semantic reasoning

M07 MUST NOT send an unordered collection of all observations directly to a reasoning model.

The pipeline first determines which observations belong to the same temporal reasoning window.

```text
Audio observations
Visual observations
        │
        ▼
Temporal correlation
        │
        ▼
Evidence Group
        │
        ▼
Semantic reasoning
```

This creates deterministic reasoning boundaries and makes replay possible.

---

## D4 — Existing MediaSegment windows remain the temporal anchor

M07 MUST reuse the segmentation semantics introduced by M04.

M07 MUST NOT introduce another independent media segmentation algorithm.

Where possible:

```text
MediaSegment
   ├── AudioObservation
   └── VisualObservation
```

Observations associated with the same content and compatible temporal window form the primary correlation unit.

M07 MAY internally support correlation across adjacent windows if required by an explicit future rule, but cross-window state is NOT part of the initial M07 implementation.

Initial implementation:

```text
one MediaSegment window
        ↓
one reasoning unit
```

---

## D5 — Evidence references are first-class

Every ContextEvent produced by M07 MUST be traceable to the observations that supported it.

M07 MUST use the stable observation identifiers created in M05/M06.

Where the existing ContextEvent v1 contract supports timestamp-level visual evidence references, M07 MUST preserve those timestamps.

A context result with no supporting evidence MUST NOT be emitted.

No fabricated evidence references are allowed.

---

## D6 — Perception confidence is not calibrated probability

Visual confidence from M06 is model-verbalized and uncalibrated.

M07 MUST NOT interpret:

```text
confidence = 0.90
```

as:

```text
90% probability that the observation is correct
```

M07 MUST NOT average audio/visual confidence values to derive ContextEvent confidence.

M07 MUST NOT use arbitrary formulas such as:

```text
(audioConfidence + visualConfidence) / 2
```

unless a future ADR explicitly defines and validates such semantics.

Perception confidence MAY be provided to semantic reasoning as evidence metadata.

---

## D7 — Context reasoning is model-agnostic

The context domain MUST NOT depend on OpenAI, Gemini, Claude, llama.cpp, Qwen, Whisper or any provider-native type.

M07 introduces a vendor-neutral reasoning port.

Provider-specific reasoning implementations MUST remain behind adapters.

---

## D8 — No commerce reasoning

M07 answers:

```text
What is happening in the content?
```

It does NOT answer:

```text
What should be sold?
Which product should be recommended?
Which offer should be displayed?
Which retailer should be selected?
```

Commerce fields, ranking, product matching, prices, offers and recommendations remain outside Context Intelligence.

A visually detected BRAND remains evidence, not a commercial recommendation.

# 5. Internal evidence model

Do NOT introduce new public contracts called AudioEvidence or VisualEvidence.

AudioObservation and VisualObservation remain the canonical perception evidence.

M07 MAY create an internal normalized representation for reasoning.

Example:

```go
type EvidenceKind string

const (
    EvidenceAudio  EvidenceKind = "AUDIO"
    EvidenceVisual EvidenceKind = "VISUAL"
)

type EvidenceRef struct {
    ObservationID string
    TimestampMs   *int64
}

type Evidence struct {
    Kind          EvidenceKind
    ObservationID string
    TimestampMs   *int64

    Type          string
    Value         string
    Text          string

    Confidence    *float64
}
```

This representation is internal only.

It MUST NOT become another external schema.

It exists to make multimodal reasoning provider-independent.

# 6. Observation collection

M07 receives the outputs produced by the audio and vision pipelines for the same media input.

For every MediaSegment:

```text
segment
   │
   ├── zero or one AudioObservation
   │
   └── zero or one VisualObservation
```

A reasoning unit MAY contain:

```text
audio only
vision only
audio + vision
```

M07 MUST NOT require both modalities to emit a ContextEvent.

This is important because real media may contain:

- dialogue with visually irrelevant frames;
- purely visual context;
- silence;
- blank frames;
- model failures;
- empty detections.

Missing modality is not automatically an error.

# 7. Temporal correlation

Introduce a deterministic correlation component.

Suggested port:

```go
type Correlator interface {
    Correlate(input CorrelationInput) ([]EvidenceGroup, error)
}
```

Initial M07 implementation uses a segment-based correlator.

Example:

```go
type CorrelationInput struct {
    Segment contracts.MediaSegment

    Audio  []contracts.AudioObservation
    Visual []contracts.VisualObservation
}
```

Output:

```go
type EvidenceGroup struct {
    ContentID string
    Window    contracts.TimeWindow
    Evidence  []Evidence
}
```

Rules:

1. observations MUST belong to the same content;
2. observation windows MUST be compatible with the MediaSegment;
3. evidence ordering MUST be deterministic;
4. audio evidence precedes visual evidence only if their effective timestamp requires it;
5. visual frames use their actual `timestampMs`;
6. duplicate evidence references are rejected;
7. empty evidence groups produce no candidate.

Deterministic ordering:

```text
timestamp
then evidence kind
then observationId
then stable item order
```

This is required for reproducible replay and tests.

---

# 8. Audio evidence projection

AudioObservation is projected internally without altering the original observation.

Conceptually:

```text
AudioObservation
    │
    ├── transcript.text
    ├── language
    ├── confidence?
    └── observationId
```

becomes reasoning evidence approximately equivalent to:

```text
kind = AUDIO
observationId = ...
text = transcript.text
```

Empty transcript remains valid evidence but MAY be excluded from semantic reasoning if it contains no usable semantic content.

Raw provider markers MUST NOT be silently rewritten.

If filtering provider markers becomes necessary, that requires an explicit later decision.

---

# 9. Visual evidence projection

Each VisualObservation frame is projected independently.

Conceptually:

```text
VisualObservation
    │
    └── frame
         ├── timestampMs
         ├── description
         └── observations[]
```

Each detection can become internal reasoning evidence:

```text
kind          = VISUAL
observationId = visual observation ID
timestampMs   = frame timestamp
type          = OBJECT | ENTITY | TOPIC | BRAND | TEXT | SCENE | ACTION
value         = detection value
confidence    = provider-reported value
```

Frame description MAY also be passed as contextual evidence but MUST NOT generate an invented detection.

An empty observations list remains legitimate evidence that nothing structured was detected.

---

# 10. Context Candidate

Correlation produces an EvidenceGroup.

Before generating a ContextEvent, M07 creates an internal ContextCandidate.

Example internal model:

```go
type Candidate struct {
    ContentID string
    Window    contracts.TimeWindow

    Evidence []EvidenceRef

    ContextType string
    Label       string
    Attributes  map[string]string

    ReasoningMetadata ReasoningMetadata
}
```

IMPORTANT:

This is NOT a new external contract.

Exact fields SHOULD be adapted to what is actually required to build the existing ContextEvent v1.

Do not modify ContextEvent v1 merely to match this example.

If the existing ContextEvent contract does not support one of these fields, omit it from the internal structure or keep it purely internal.

---

# 11. Semantic Reasoning port

Introduce a vendor-neutral reasoning interface.

Recommended shape:

```go
type Reasoner interface {
    Reason(
        ctx context.Context,
        group EvidenceGroup,
    ) ([]Candidate, error)
}
```

A reasoner:

- receives already-correlated evidence;
- MUST NOT perform media extraction;
- MUST NOT call STT;
- MUST NOT extract video frames;
- MUST NOT own segmentation;
- MUST NOT modify source observations.

Its only responsibility is:

```text
EvidenceGroup
     ↓
semantic interpretation
     ↓
ContextCandidate(s)
```

---

# 12. Reasoning input

Provider-specific adapters receive a compact deterministic representation.

Example conceptual input:

```json
{
  "contentId": "example",
  "window": {
    "startMs": 10000,
    "endMs": 15000
  },
  "evidence": [
    {
      "kind": "AUDIO",
      "observationId": "aud:example:10000-15000",
      "text": "agora vou colocar o azeite"
    },
    {
      "kind": "VISUAL",
      "observationId": "vis:example:10000-15000",
      "timestampMs": 12500,
      "type": "OBJECT",
      "value": "olive_oil_bottle",
      "confidence": 0.87
    },
    {
      "kind": "VISUAL",
      "observationId": "vis:example:10000-15000",
      "timestampMs": 12500,
      "type": "ACTION",
      "value": "pouring",
      "confidence": 0.84
    }
  ]
}
```

Confidence is metadata only.

Prompt/instructions MUST explicitly state that confidence values are uncalibrated model outputs and must not be interpreted as probabilities.

# 13. Reasoning output

The reasoning adapter MUST return structured output.

No free-form prose may flow directly into the domain.

The adapter parses provider output into adapter-private structures and maps them to `Candidate`.

Malformed provider output rejects that reasoning result.

Do not:

- repair malformed JSON silently;
- invent missing evidence;
- clamp invalid numeric values;
- invent taxonomy values;
- accept unknown fields silently if strict parsing is feasible.

---

# 14. Evidence grounding rule

Every candidate MUST reference at least one input evidence item.

The reasoner MUST NOT be allowed to return arbitrary observation IDs.

During mapping:

```text
candidate evidence references
            ↓
validate against EvidenceGroup
            ↓
ContextEvent
```

If a reasoner references:

```text
unknown observationId
```

the result is rejected.

For visual evidence, a referenced timestamp MUST correspond to a frame actually present in that VisualObservation.

This is the main hallucination containment boundary in M07.

---

# 15. Multimodal agreement and disagreement

M07 MUST NOT assume modalities always agree.

Examples:

```text
Audio: "vou pegar o café"
Vision: wine_glass
```

or:

```text
Audio: no useful speech
Vision: football_match
```

The reasoning stage MUST be allowed to:

- use one modality;
- use both modalities;
- reject insufficient evidence;
- return no ContextEvent.

The implementation MUST NOT artificially force fusion.

"Multimodal" means multiple modalities are available for reasoning, not that every conclusion must use every modality.

---

# 16. ContextEvent mapping

Introduce a mapper:

```go
func NewContextEvent(
    group EvidenceGroup,
    candidate Candidate,
    pipelineVersion string,
) (contracts.ContextEvent, error)
```

The mapper MUST conform to the existing ContextEvent v1 contract.

M07 MUST NOT change the ContextEvent schema unless an actual incompatibility is discovered and explicitly reported.

Mapping rules:

- content identity derives from the MediaSegment;
- temporal boundaries derive from the correlated reasoning window;
- evidence references derive from validated Candidate evidence refs;
- provenance derives from the context reasoning provider;
- pipelineVersion is required;
- no commerce fields;
- no provider-native types.

The final result MUST pass:

```text
contracts.Validate
+
existing JSON-schema validation
```

through the M03 runner.

# 17. ContextEvent identity

ContextEvent IDs MUST be deterministic if the existing contract allows M07 to construct them.

The identifier MUST NOT depend on:

- current time;
- random UUID;
- filesystem paths;
- provider process IDs;
- unordered map iteration.

The exact deterministic ID algorithm MUST be derived from the existing ContextEvent contract and ADRs.

If the existing specification already defines ContextEvent identity, M07 MUST follow it rather than introducing another scheme.

# 19. Execution order

Initial M07 implementation remains sequential and deterministic.

For every segment:

```text

2. visual perception
3. correlation
4. semantic reasoning
5. ContextEvent mapping
```

or equivalent deterministic execution that preserves the same result.

Parallelism remains deferred until measurements justify it.

Correctness and reproducibility take precedence over throughput in M07.

                  │

```text

```

```text
VLM response = ContextEvent
```

Provider output must cross the Context Reasoning boundary and be validated/mapped first.

# 29. Suggested ADR

Add an ADR documenting:

## Title

Observations are immutable perception evidence and ContextEvents are derived semantic conclusions

## Decision

AudioObservation and VisualObservation are treated as immutable perception evidence.

Context reasoning first correlates observations temporally, then applies semantic reasoning, and only then produces ContextEvents.

ContextEvents retain references to the observations supporting the conclusion.

Perception confidence remains evidence metadata and is not interpreted as calibrated probability by the Context Engine.

## Consequences

Positive:

- provider-independent domain;
- explainable ContextEvents;
- deterministic correlation;
- replay capability;
- model replacement without ContextEvent consumer changes;
- easier evaluation of perception vs reasoning;
- hallucination containment through evidence validation.

Trade-offs:

- additional internal reasoning structures;
- more validation;
- more explicit orchestration;
- potentially higher implementation complexity than direct model-to-ContextEvent mapping.

Rejected alternative:

```text
Audio + frames → VLM/LLM → ContextEvent directly
```

because it couples perception, temporal correlation and semantic interpretation and weakens replay/debug traceability.

# 30. Risks

## R1 — Semantic hallucination

Reasoner may produce conclusions unsupported by evidence.

Mitigation:

```text
mandatory evidence references
+
reference validation
+
structured output
```

## R2 — Visual confidence misuse

M06 visual confidence is not calibrated.

Mitigation:

M07 treats it as descriptive evidence metadata only.

## R3 — Label drift

Different models may use semantically equivalent but lexically different labels.

M07 MUST NOT silently introduce a normalization ontology unless already defined by existing specs.

Any normalization/taxonomy policy belongs to an explicit contract or decision.

## R4 — Window boundary context loss

One-segment reasoning may miss context spanning adjacent segments.

Accepted for initial M07.

Cross-window temporal state may be introduced later after M08/M09 evidence.

## R5 — Cost / latency

Running audio + vision + semantic reasoning can be expensive.

Measurement and optimization are deferred.

M07 prioritizes architectural correctness.
